## 1. 背景与目标

`钟灵毓秀`（https://zhixia.pages.dev/）是 zhongling 的个人博客，2022-04-14 开站，至今 **36 篇文章**、约 18 万字符、239 次提交。

> **篇数口径**：以 `hugo list published` 为准 —— `content/posts/` 下共 37 个 `.md`，其中 `_index.md` 是栏目页而非文章，故实际 **36 篇**。分布：2022 年 5、2023 年 2、2024 年 6、2025 年 11、2026 年 12，合计 36。视频中出现的一切篇数必须与此一致。内容横跨 AI Agent 工程、RAG 检索、AI 编程、软件架构，以及古典文学札记与生活思考。

**目标**：做一支 68 秒的介绍片，嵌在博客站内（首页 hero 或关于页），让第一次到访的人在静音状态下也能明白「这里有什么、作者是个什么样的人」。

**叙事主线**：作者成长线，第一人称。不讲"本站有五大分类"，讲"一个人四年半怎么变的"。

**主风格**：A 墨色编辑（宣纸底 + 宋体 + 朱红印章），结尾转 B 终端工程（深色终端 + 等宽字体）。结尾的风格切换是叙事上的"揭底"——观众最后才发现这位抄书的人是工程师。

### 3.2 字体

使用 **macOS 系统字体**（用户明确选择，不引入 webfont、不联网）：

| 用途 | 字体栈 |
| --- | --- |
| 标题 | `Songti SC`, `Noto Serif SC`, serif |
| 正文 | `PingFang SC`, `Hiragino Sans GB`, sans-serif |
| 数据 / 终端 | `SF Mono`, Menlo, monospace |

**已知约束**：系统字体只在 macOS 上存在。渲染必须在作者的 Mac 上执行；在其他机器或 CI 上渲染会回退到别的字体，画面与预期不符。本项目不为此做兼容处理。

### 3.3 动效原则

- 缓动统一：`Easing.bezier(0.22, 1, 0.36, 1)`
  **唯一例外**：第 8 拍那条横扫的朱红线用 `Easing.inOut(Easing.quad)`。上面这条曲线是前倾的 —— 给透明度/位移的"入场"正合适，但用在一条横向扫过画面的线上，会让它第 3 帧就盖过九成屏宽、第 4 帧扫完全程，之后却要二十来帧才慢慢退出画面，读到的是闪光接一段拖尾，而不是"扫过"。位移型的横扫需要对称曲线。此事在实现过程中发现并记录（见计划 Task 10）。
- 文字入场：透明度 0→1，配 8–12px 上移，无弹跳
- **全片仅一处"重"动效**：第 1 拍朱红印章落下（scale 落下，落定前有轻微回弹）
- 每一拍进场后静置 0.5–1 秒再出：静音视频靠停留让人读完字
- 第 3 拍（2023 停笔）反向处理——几乎全静止，对比度主动压低

### 4.1 第 6 拍选定的 3 篇

按用户决定从 5 篇砍到 3 篇。选中的三篇构成一条逐级上升的弧线：

1. **LangGraph 深度学习** —— 学引擎
2. **从 Dify Graphon 到 LangGraph：工作流引擎的调度、状态与性能** —— 比引擎
3. **让 AI 一边生成一边搭界面：LLM 渐进式渲染的一个专利思路** —— 造引擎

落选的 Agent HITL 设计、BM25 + Milvus 混合检索不再出现在画面文字中。

### 4.2 转场

- **3 → 4**：靠"停顿"转场。第 3 拍静止收尾，第 4 拍朱红年份色回归，形成节奏上的重启
- **7 → 8**：主转场。宣纸层整体淡出（配单向横线扫过），终端层淡入。这是全片唯一一次背景色反转

### 5.1 组件职责

| 组件 | 做什么 | 依赖 |
| --- | --- | --- |
| `Paper.tsx` | 铺宣纸底色与纸纹，作为大部分镜头的底层 | `theme.ts` |
| `Seal.tsx` | 给定文字与位置，播放印章落下动画 | `theme.ts` |
| `InkLine.tsx` | 给定宽度与位置，从左展开一条细线 | `theme.ts` |
| `YearCard.tsx` | 接收一个年份对象，渲染年份大字 + 动词 + 篇名；`subdued` 变体供第 3 拍使用 | `theme.ts`、`data/posts.ts` 的年份类型 |
| `Timeline.tsx` | 渲染 2022→2026 时间轴与札记实线 | `data/posts.ts` |
| `Typewriter.tsx` | 接收文本与帧号，逐字输出 | 无 |
| `TerminalCard.tsx` | 组合多行 `Typewriter` 成终端画面 | `Typewriter.tsx`、`theme.ts` |

### 5.2 数据模型

`src/data/posts.ts` 导出：

```ts
export type YearEntry = {
  year: number;
  verb: string;          // 搬 / 学 / 做 / 造
  posts: string[];       // 画面展示的篇名（可少于 count，按展示需要裁剪）
  count: number;         // 该年实际篇数，用于派生校验
  subdued?: boolean;     // 第 3 拍的低对比变体
};

export const years: YearEntry[];
export const totalPosts: number;   // 36
export const siteUrl: string;      // zhixia.pages.dev
export const closingLine: string;  // 技术是工作，抄书是日子。
```

各年 `count` 必须为 5 / 2 / 6 / 11 / 12（合计 36）。`posts` 只放画面上要显示的篇名，第 4、5 拍各显示 4 篇而实际 `count` 为 6 / 11，这是有意的裁剪。

**设计意图**：全部文案集中在数据文件里。以后想换第 6 拍的三篇、改落版那句话、调年份措辞，只改这个文件，不碰任何动画代码。

## 6. 验证方式

Remotion 项目不做组件单元测试，验证靠视觉与产物检查：

1. `npx remotion studio` 逐帧检视 8 个镜头，重点核 3→4 与 7→8 两个转场衔接
2. `npx remotion render` 出 mp4，核对：时长 68 秒、体积合理、**静音播放信息完整**
3. 嵌入站内实际查看一次

对 `data/posts.ts` 的派生逻辑写一个测试兜住，避免改数据时算错：

- `totalPosts` 必须等于各年 `count` 之和（36）
- 各年 `count` 必须与 `hugo list published` 的实际结果一致（5 / 2 / 6 / 11 / 12）
- `posts` 中每个篇名必须真实存在于 `content/posts/`，防止笔误或已删文章留在画面上
